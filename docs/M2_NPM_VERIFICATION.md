## Behavior and safety

Project inventory is opt-in. Enter one local absolute project directory and use **開始 npm 唯讀掃描**. Windows inventory remains a separate snapshot; only one scan runs at a time. Cancellation and stable errors are visible. Project paths remain transient input; SQLite and IPC inventory contain path/slot hashes. There is no advisory request or inventory upload.

Only `npm-shrinkwrap.json`, `package-lock.json` and optional `package.json` are read. Shrinkwrap takes precedence; a corrupt preferred file is an error rather than a silent fallback. `.npmrc`, project source, lifecycle scripts and installed `node_modules` files are not read or executed. pnpm/Yarn markers produce unsupported-format/gap codes; their lockfiles are not parsed. No npm/Node/package-manager binary is invoked, dependency installed or privilege requested.

Lockfile v1/v2/v3 declarations retain exact SemVer observations, aliases, separate nested/hoisted slots and dependency edges. Logical workspace links resolve inside JSON metadata only; they never cause filesystem traversal. Direct/transitive relationships are conservative: v1 needs root manifest declarations; malformed/missing root metadata leaves UNKNOWN relationships. Invalid/missing versions and unresolved/malformed links keep UNKNOWN versions. Dependency and optional/dev/peer/link-target edge kinds remain explicit.

`NPM_REGISTRY_METADATA` describes a declared npm registry URL, not proof of a public package or trusted installation. npm registry can contain private packages. Raw URLs, credentials and private registry hosts are discarded; this collector makes no network request. Lockfile declarations do not prove the package is installed, the manifest is truthful, or a vulnerability applies. Coverage stays PARTIAL with `LOCKFILE_DECLARATIONS_NOT_INSTALLED_PROOF`.

## Bounds and boundary checks

Accept only local fixed/RAM drives, no UNC/network roots, alternate streams, traversal components or reparse points. Root acquisition opens each ancestor from drive root down with `OPEN_REPARSE_POINT`, retains handles without DELETE sharing, and compares final handle paths to the selected spelling. Windows 8.3 names expand using `GetLongPathNameW` after handles are held. Unexpected aliases fail closed. File handles are checked before content reads; metadata hard links are rejected. Unsupported filesystem/ACL/canonicalization cases produce stable errors rather than broader traversal.

Limits: lockfile 8 MiB, optional manifest 1 MiB, 20,000 package slots, 50,000 edge pairs, legacy depth 64 and link chain 16. JSON recursion is also bounded. Descriptor references borrow the parsed tree instead of repeatedly cloning large nested payloads. The product launches only its own executable, passes the selected root through private stdin, uses an owned temporary working directory and Windows Job, and kills/waits only its child on cancellation or a 15-second deadline. Output is capped at 32 MiB. Errors never echo subprocess output or root paths.

SQLite schema v3 upgrades v1 Windows history and preview v2 project graphs, separates Windows/npm latest scans, retains UNKNOWN direction, enforces graph/environment foreign keys and stores immutable per-scan graph JSON. Catalog rows can remain for history/finding references; `environment_current_packages` alone defines the latest successful graph's membership. Rescans update mutable name/version/source metadata and replace membership/edges, including removed packages or an empty graph, without changing past snapshots. Migration003 reconstructs existing preview membership and current alias metadata from the latest successful graph. Restart restores the selected scope; interrupted scans are explicit. UI pagination renders at most 200 package rows at once and provides dependency inspection.
